# Research note — On-policy "league" reach-avoid PPO at mjlab scale (future work)

**Status:** idea / not implemented. Recorded 2026-06-27 while building the ISAACS
Tier-2 SAC port (`src/isaacs_go2/`, `safety_sb3.IsaacsSAC`).

## Motivation

mjlab's headline strength is **thousands of GPU-parallel envs**, which is ideal
for **on-policy** PPO (it consumes huge fresh batches per update). The canonical
ISAACS (this repo's Tier 1/2) is **off-policy SAC**, chosen *not* because of
reach-avoid but because the **leaderboard** — archiving past disturbance policies
and bootstrapping rollouts against them — is intrinsically off-policy (it reuses
data generated by *old* policies). Off-policy SAC's parallelism saturates early
(~32–64 envs: past that the replay buffer becomes correlated and the
gradient-update-per-transition ratio collapses), so it leaves most of mjlab's
throughput on the table on the adversarial problem.

The reach-avoid Bellman backup itself (`min(g, max(l, γV'))`) is perfectly happy
on-policy — `src/tasks/parkour/rl/reach_avoid_ppo.py` (`ReachAvoidPPO`, rsl_rl)
already runs it at thousands of envs. The open question is whether we can keep
that full parallelism **and** recover the leaderboard's strategy-space
regularization for the two-player adversarial game.

## Core idea — opponent population *across the env batch* (PFSP / league self-play)

The leaderboard's real job is **opponent diversity in the trainee's data**. SAC
gets it *temporally* for free (one replay buffer mixes opponents over time).
On-policy, engineer the same diversity *spatially*:

- Run a large parallel batch (e.g. 4096 envs).
- **Assign different frozen archived disturbance policies to different envs**,
  sampled by the same softmax-rationality rule as `safety_sb3/leaderboard.py`
  (`p ∝ exp(-rationality · avg_metric)` — disturbances that drive the control's
  reach-avoid value down get more envs).
- One fresh on-policy PPO batch then already contains control rollouts against a
  *population* of disturbances → strategy-space regularization without
  off-policy bootstrap. This is the AlphaStar-league / PFSP trick (Prioritized
  Fictitious Self-Play), proven to scale with parallel actors.

## Sketch

- **Control update (max player):** standard `ReachAvoidPPO`, but each env's
  disturbance action comes from a per-env-assigned frozen archived dstb policy
  (run all archived dstb nets in inference on their slice of the batch). The
  reach-avoid reward/critic is unchanged.
- **Disturbance update (min player):** alternate. Freeze the control population
  (recent archived ctrl snapshots, also spread across the batch), train a dstb
  PPO to *minimize* the reach-avoid value against them. Negate the RA advantage
  for the min player (or learn a separate dstb critic).
- **League/leaderboard:** reuse `Leaderboard` (archive, evict-worst, softmax
  sample) — but sample assigns opponents to **env slices** each rollout instead
  of seeding a replay buffer. Periodically snapshot current ctrl/dstb into the
  archive.
- **Schedule:** alternate ctrl-phase / dstb-phase (RARL-style), each phase a
  few PPO epochs over the parallel batch; refresh opponent assignment per
  rollout.

## Trade-offs / open problems

- **Pro:** full mjlab parallelism (10²–10³× the SAC sample rate); rsl_rl-native,
  reuses `ReachAvoidPPO` + existing mjlab vec-env + the Go2 parkour-safety stack
  directly (no Gymnasium↔SB3 bridge).
- **Con / risk:** departs from canonical ISAACS (off-policy archive bootstrap →
  on-policy population). The **disturbance half is the hard part**: on-policy
  min-player PPO against a moving control population can still cycle; needs the
  alternation + archive to damp it. Tuning the ctrl/dstb phase ratio and the
  per-env opponent mixture is non-trivial.
- **Validation:** compare robust reach-avoid value / fall-rate-under-worst-case
  vs the SAC ISAACS baseline (Tier 2/3). If the league PPO matches ISAACS'
  worst-case robustness at ≫ throughput, it's the better fit for mjlab.
